# Value Metrics — Encontrar, Validar e Precificar

> Capítulo 8–9 | Product-Led Growth — Wes Bush

## Definição

> **Value metric** = como você mede a troca de valor no produto.

Tipos:
- **Functional**: escala por uso ("per user", "per 100 videos")
- **Outcome-based**: cobra por resultado (receita gerada, emails enviados)

**Outcome-based supera feature differentiation:**
- 75% menos churn
- +40% redução adicional de churn vs. functional
- +50% expansion revenue

---

## 3 Critérios de uma Boa Value Metric

1. **Fácil de entender** — visitante da pricing page sabe imediatamente pelo que está pagando?
2. **Alinhada com valor entregue** — mede o que é necessário para o cliente alcançar o outcome?
3. **Cresce com o uso** — quanto mais valor, mais paga naturalmente?

Exemplos:
- Wistia → vídeos uploadados
- Slack → mensagens enviadas (+ network effects = per-user funciona)
- PayPal → receita gerada

## Passo a Passo

### Step 1: Análise Subjetiva
1. Liste hipóteses de value metric
2. Passe pelo scratch pad → `../templates/value-metric-scratch-pad.md`

### Step 2: Data-Driven
Analise padrões entre melhores vs. piores clientes:

**Melhores clientes:**
- O que fazem regularmente no produto?
- O que NÃO fazem?
- Quais features tentaram primeiro?
- Que similaridades levaram ao sucesso?

**Churned customers:**
- Quais diferenças no user journey?
- Quais atividades eram diferentes?
- Por que a maioria churnou?

### Step 3: Stress Test (Relative Preference Analysis)
```
Em termos de [produto], qual das seguintes cobranças
você prefere MAIS? Qual prefere MENOS?
[ ] Por [métrica A]  [ ] Por [métrica B]
[ ] Por [métrica C]  [ ] Por [métrica D]
```
Envie para clientes e PQLs. Mais respostas = mais preciso.

## Armadilha: Per-User Pricing

> "Per-user pricing mata seu crescimento porque raramente reflete onde o valor está."
> — Patrick Campbell, ProfitWell

**Por que é ruim (na maioria dos casos):**
- Incentiva o cliente a limitar uso para controlar custos
- Reduz adoção dentro da empresa
- Desacopla preço de valor entregue

**Quando per-user funciona (todos devem ser True):**
- [ ] Todo usuário tem papel único e ativo no produto
- [ ] Adicionar usuário aumenta valor do produto (network effects)
- [ ] Fácil de entender e controlar quantidade
- [ ] Clientes não vão limitar adoção por causa do custo
