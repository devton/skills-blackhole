# Triple A Sprint — Processo Mensal de Otimização PLG

> Capítulo 12 | Product-Led Growth — Wes Bush

## Goal
Construir processo sustentável de crescimento mensal. Ciclo: Analyze → Ask → Act.

---

## As 3 Alavancas de Crescimento

```
Churn > ARPU > # Customers
```

- Empresa com -5% churn tem **73% mais receita** vs empresa com +5% churn (Tomasz Tunguz)
- -30% churn + +30% ARPU + +30% clientes = **+100% LTV** (Drew Sanocki)

---

## A1 — Analyze
*1º dia útil do mês, 1–2 horas bloqueadas.*

### 6 Macro Outputs
1. # Signups
2. # Upgrades
3. ARPU
4. Customer Churn %
5. ARR
6. MRR

Compare com últimos 12 meses. Área que mais sofreu = foco do sprint.

**Diagnóstico:**
- Signups caindo → Understand/Communicate Value
- Upgrades baixos → Ability Debt ou Value Gap em Deliver
- Churn alto → UCD qualquer + má qualidade de clientes
- ARPU estagnado → pricing, upsell, wrong customers

---

## A2 — Ask

**1. Onde quer chegar?**
Objetivo numérico claro. Use OKRs (Measure What Matters, John Doerr).

**2. Qual alavanca puxar?**
Simule +20% em cada alavanca separadamente. Maior variação de MRR = sua prioridade.

**3. Quais inputs investir?**

Root cause sempre cai em um dos 3 (UCD):
1. Não entende valor → improve Understand
2. Não comunica bem → improve Communicate
3. Não entrega rápido → improve Deliver

**Dica:** compre seu próprio produto uma vez por mês. Você vai encontrar ability debt ridículo.

**ICE Score (Sean Ellis):**

| Dimensão | Pergunta |
|---|---|
| **I**mpact | Qual impacto potencial no output? |
| **C**onfidence | Quão confiante estou de que vai funcionar? |
| **E**ase | Quão fácil de implementar? |

`ICE = (I + C + E) / 3` — selecione 1–2 de maior ICE.

## A3 — Act

- Implemente 1–2 inputs selecionados
- Primeiro sprint: quick wins (alta facilidade)
- Sprints futuros: big swings
- Meça resultado no próximo ciclo

**Fluxo HubSpot (Kieran Flanagan):**
1. Set a visão de longo prazo
2. Quick wins para build trust com liderança e eng
3. Itere em direção à visão
4. Escale complexidade gradualmente

---

## Erros Comuns

- Obsessão com vanity metrics (bounce rate, email opens) em vez de macro outputs
- Focar só em # customers, ignorar ARPU e churn
- Não ter alguém dono do processo
- Implementar muitas ideias de uma vez (não mede impacto individual)
